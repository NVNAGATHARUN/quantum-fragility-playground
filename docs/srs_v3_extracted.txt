3. Final Product Definition

FROZEN DEFINITION

Quantum Lens AI is an adaptive quantum learning laboratory where a learner studies a concept, predicts circuit behavior, builds visually or in code, executes verified quantum simulations, observes state evolution, compares expectation with reality, receives grounded guidance, tests conceptual misunderstandings through targeted experiments, and builds measurable mastery.

3.1 Product goals

Make abstract quantum behavior observable, manipulable and testable.

Turn simulation into a teaching mechanism rather than a result viewer.

Make visual circuit construction and code construction two views of the same canonical program.

Make multi-framework support real and inspectable.

Make AI a grounded tutor and code assistant, never the physics engine.

Measure learning from actual evidence and attempts, not arbitrary completion percentages.

Give instructors real class-level evidence about concept mastery and recurring misconceptions.

Deliver a product-quality website that can be used without a presenter.

3.2 Explicit non-goals

No attempt to replace IBM Quantum Platform, qBraid Lab or a full research cloud IDE.

No unrestricted arbitrary Python execution in the application server.

No realtime Google-Docs-style circuit collaboration in the SIH core.

No social feed, NFT/blockchain certificate system, metaverse or decorative AI agents.

No manufacturing-grade digital-twin claim for the Hardware Explorer.

No unsupported quantum-advantage claims.

No 50-algorithm catalog at the cost of incomplete core functionality.

11.1 IR rules

The IR is the single source of truth for the visual circuit.

Visual edits update IR; code import compiles to IR; backend adapters consume IR.

IR is versioned and validated before execution.

Unsupported operations fail explicitly; they are never silently ignored.

Circuit hashes support reproducibility and result caching where safe.

11.2 Code modes

Primary fully editable language. Validate/compile with real parser tooling; import/export supported. Legacy OpenQASM 2 import may be supported.

PennyLane

SECURITY RULE

Do not execute arbitrary user Python with eval/exec/subprocess on the application server. If a future general Python sandbox is added, it must be isolated with CPU/memory/time/network restrictions.

12.3 Resource limits

Limits are based on actual deployment memory, not marketing. Before execution the backend estimates memory/cost and rejects unsafe jobs with a clear message. Statevector and density-matrix limits are independently configurable. The hosted demo should prefer small, reliable circuits rather than claiming unrealistic qubit counts.

12.4 Cross-framework parity

A parity suite runs reference circuits through Qiskit, PennyLane and Cirq and compares normalized probabilities/state outputs within numeric tolerance. Framework discrepancies block release for the affected operation set.

13. Quantum State and Result Visualization

Single qubit: Bloch sphere, amplitudes/probabilities and phase.

Multi-qubit: explicit statevector table/visualization, probability histogram, amplitude/phase view and correlation view.

Reduced Bloch spheres are allowed only when clearly labeled as reduced single-qubit states.

Entangled states must not be represented as independent pure Bloch vectors.

Measurement results display counts and probabilities with consistent scales.

Every chart includes title, units/definition where relevant, tooltip and beginner explanation.

Every result shows source badge: LOCAL PREVIEW, QISKIT AER SIMULATOR, PENNYLANE SIMULATOR, CIRQ SIMULATOR, QBRAID CLOUD, or QPU if ever configured.

13.1 Gate-by-gate timeline

The learner can scrub operation/layer steps. Selecting a step highlights the circuit operation and updates the verified state/result view. For an H→CX Bell circuit, the timeline must show the true global two-qubit state after CX, not a heuristic shrink animation.

14. Circuit Insights — Optimize, Compare, Verify

This subsystem satisfies the PS requirement for optimization suggestions while adopting the verification discipline seen in engineering-oriented platforms such as QForge.

Compute real metrics: gate count, depth, two-qubit gate count/depth, parameter count and selected backend constraints.

Provide deterministic safe rewrite suggestions first: inverse/canceling pairs, adjacent rotation merges and supported decompositions.

AI may propose an optimization, but it cannot be applied until a deterministic verifier accepts it.

For small unitary circuits, verify equivalence via unitary/state equivalence within tolerance.

For non-unitary/noisy/measurement circuits, use appropriate behavioral tests and label them as behavioral equivalence, not mathematical proof.

Never claim global circuit optimality unless it is actually proven.

14.1 What Changed? integration

Before/after comparison includes circuit diff, metric diff, state/probability diff, verification status and grounded explanation.

Quantum measurement is inherently probabilistic, so simulator-generated sampling is legitimate. The prohibition is against arbitrary UI/business-data randomness and hand-authored physics outputs masquerading as simulator results.

30. Scientific QA and Test Strategy

30.1 Golden correctness suite

|0⟩ identity

X|0⟩ = |1⟩

H|0⟩ = |+⟩

H→H|0⟩ = |0⟩

H→Z→H|0⟩ = |1⟩

Bell preparation gives only 00/11 ideal support and correct global state

GHZ small-state reference

Basis-input CNOT and superposition-input CNOT

Known relative-phase/interference circuits

Amplitude damping / dephasing sanity cases

Cross-framework parity across supported operation set

30.2 Test layers

Unit: Circuit IR, validators, compiler, grading, evidence/mastery rules.

Adapter: IR→Qiskit/PennyLane/Cirq conversion and normalized results.

Integration: API→job→simulator→result→pedagogy.

Frontend component: circuit interactions, prediction lock, code sync, result rendering.

E2E: guest/login, lesson, lab, circuit run, challenge grading, mentor, progress and instructor assignment.

AI grounding: current result facts must be present; generated code must be rejected if validator fails.

Security: authorization/resource ownership and malicious code/input cases.

Accessibility: keyboard and automated checks plus manual critical-flow review.

3D: model load, selection, reduced-motion/fallback.

39. Final Build Contract — Non-Negotiables

• No feature exists only to impress judges.

• Quantum correctness beats visual beauty.

• Verified simulator/backend truth beats AI output.

• Pedagogical depth beats feature count.

• Working end-to-end depth beats architecture theatre.

• Production UX beats hackathon decoration.

• No fake data, no fake backend status, no fake analytics and no mocked critical flows.

• A learner must understand the primary action within seconds.

• Labs remain first-class because experimentation is the learning mechanism.

• Circuit Studio is the free sandbox; V-Labs are guided pedagogical experiences.

• Multi-framework support is real, tested and visible.

• AI-generated code is never trusted before parsing/validation.

• Optimization is never accepted before deterministic verification.

• Hardware Explorer is integrated learning, not a gimmick.

• Never claim planned/partial work as implemented.

• Preserve valid previous-project assets; replace simplified scientific logic.

• Do not redesign the frozen IA without evidence.

• Do not restart because a new coding tool/model looks attractive.

• Build → test → inspect → improve → deploy.
